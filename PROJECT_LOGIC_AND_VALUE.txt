================================================================================
ระบบสนับสนุนการทำนายหุ้นด้วยปัญญาประดิษฐ์ (TradeSensei)
คู่มือสรุปการทำงานของลอจิกต่างๆ และคุณค่าที่แท้จริงของเว็บไซต์
(สำหรับใช้ทบทวน เตรียมนักศึกษา และนำเสนอต่อคณะกรรมการสอบ)
================================================================================

--------------------------------------------------------------------------------
ส่วนที่ 1: การทำงานของลอจิกต่างๆ ในระบบ (System Logic Architecture)
--------------------------------------------------------------------------------

1. ลอจิกสายพานข้อมูลและการเตรียมข้อมูล (Data Pipeline & Preprocessing)
   - แหล่งข้อมูล: ดึงราคาหุ้นย้อนหลัง 2 ปี (ประมาณ 500 วันทำการ) จาก Yahoo Finance ผ่านไลบรารี yfinance
   - การคลีนข้อมูล: กรองค่าว่าง (NaN), ค่าอนันต์ (Inf), และราคาติดลบออกทิ้ง ป้องกันข้อผิดพลาดในระบบ
   - การแปลงสเกลด้วยคณิตศาสตร์ (Logarithmic Transformation):
     ใช้สูตร y = ln(1 + Close) หรือ np.log1p
     * เหตุผลที่ทำ: เพื่อให้โมเดลตอบสนองต่อการเปลี่ยนแปลงราคาเป็น "เปอร์เซ็นต์" อย่างเท่าเทียมกัน ไม่ว่าจะเป็นหุ้นราคา 3 บาท หรือหุ้นราคา 400 บาท หรือคริปโต
     * ป้องกันราคาติดลบ: เมื่อโมเดลทำนายเสร็จแล้วแปลงกลับด้วยสูตร Exponential (np.expm1) ราคาที่ได้จะไม่มีทางติดลบเด็ดขาด
   - การตรวจสอบความถี่ตลาดอัตโนมัติ (Market Frequency Inference):
     ระบบเขียนฟังก์ชันตรวจจับวันที่ซื้อขาย:
     * ถ้าเป็นหุ้นทั่วไป (SET, หุ้นสหรัฐฯ) -> ใช้ความถี่ 'B' (Business Days) เพื่อ "ข้ามวันเสาร์-อาทิตย์ และวันหยุดนักขัตฤกษ์" โดยอัตโนมัติ กราฟทำนายจะไม่ลงวันหยุด
     * ถ้าเป็นคริปโต (BTC, ETH) -> ใช้ความถี่ 'D' (Calendar Days) ทำนายทุกวันเพราะตลาดเปิด 24 ชั่วโมง


2. ลอจิกโมเดลพยากรณ์ราคา 7 วันล่วงหน้า (Machine Learning - Facebook Prophet)
   [ไฟล์หลัก: backend/app/services/predictor_service.py]

   2.1 วัตถุประสงค์และบทบาทของ ML ในระบบ TradeSensei:
       - ระบบนี้ใช้ Machine Learning สำหรับงาน "การพยากรณ์อนุกรมเวลา (Time-Series Forecasting)" เพื่อคาดการณ์ราคาปิด (Close Price) ล่วงหน้า 7 วันทำการ
       - ระบบไม่ได้ยืม ไม่ได้ซื้อ และไม่ได้ยิงเรียก API ทำนายผลสำเร็จรูปจากภายนอก แต่เป็น "In-House Machine Learning Pipeline" ที่เครื่องเซิร์ฟเวอร์ของเราเทรน (model.fit) และพยากรณ์ผลด้วยตัวเองบนสถาปัตยกรรมระบบภายใน

   2.2 ขั้นตอนการเตรียมข้อมูลเข้าสู่โมเดล (Data Preprocessing Pipeline):
       - ขั้นตอนที่ 1 (Data Fetching): ดึงประวัติราคาจากฐานข้อมูลตาราง historical_prices ย้อนหลัง 2 ปี (ประมาณ 500 วันทำการ)
       - ขั้นตอนที่ 2 (Data Cleaning & Minimum Threshold): กรองค่าว่าง (NaN), ค่าอนันต์ (Inf), และราคาที่ <= 0 ออกทิ้ง และตรวจสอบเงื่อนไขความปลอดภัยว่าต้องมีข้อมูลราคาที่สมบูรณ์อย่างน้อย 60 วันทำการ (MIN_HISTORY_DAYS = 60) หากไม่พอ ระบบจะแจ้งเตือนให้ดึงข้อมูลก่อนเพื่อป้องกันโมเดลเทรนผิดพลาด
       - ขั้นตอนที่ 3 (Logarithmic Transformation): แปลงข้อมูลราคาปิดด้วยฟังก์ชันคณิตศาสตร์:
         y = ln(1 + Close Price) หรือคำสั่ง np.log1p(Close)
         * ทำไมต้องทำ: ในตลาดการเงิน ราคาหุ้นแต่ละตัวมีสเกลต่างกันมาก (เช่น หุ้นราคา 3 บาท กับหุ้นราคา 400 บาท หรือคริปโตราคาหลักล้าน) การใช้ Log Scale ทำให้โมเดลเรียนรู้และตอบสนองต่อการเปลี่ยนแปลงราคาเป็น "เปอร์เซ็นต์สัมพัทธ์ (Relative Percentage Returns)" อย่างเป็นธรรมเท่าเทียมกันทุกตัว
         * ป้องกันราคาติดลบเด็ดขาด: เมื่อโมเดลทำนายเสร็จและแปลงกลับด้วยฟังก์ชัน Exponential (np.expm1) ราคาผลลัพธ์ทางคณิตศาสตร์จะไม่มีทางต่ำกว่าศูนย์เด็ดขาด
       - ขั้นตอนที่ 4 (Market Frequency Inference): ระบบมีฟังก์ชันตรวจสอบพฤติกรรมวันที่ของสินทรัพย์อัตโนมัติ (_infer_market_frequency):
         * ถ้ามีข้อมูลซื้อขายในวันเสาร์-อาทิตย์ (weekday >= 5) เช่น คริปโตเคอร์เรนซี (BTC, ETH) -> ใช้ความถี่ 'D' (Calendar Days) ทำนายต่อเนื่องทุกวันตลอด 24/7
         * ถ้าไม่มีข้อมูลวันหยุด เช่น หุ้นไทย (SET50), หุ้นสหรัฐฯ, สินค้าโภคภัณฑ์ -> ใช้ความถี่ 'B' (Business Days) เพื่อ "ข้ามวันเสาร์-อาทิตย์ และวันหยุดตลาด" โดยอัตโนมัติ เส้นกราฟทำนายจะไม่ไปตกในวันหยุด

   2.3 การกำหนดโครงสร้างโมเดลและไฮเปอร์พารามิเตอร์ (Model Architecture & Hyperparameters):
       - โครงสร้างโมเดลอ้างอิงสมการ Generalized Additive Model (GAM) ของ Facebook Prophet:
         y(t) = g(t) + s(t) + h(t) + e(t)
         โดยประกอบด้วย แนวโน้มหลัก (Growth Trend) + ฤดูกาล (Seasonality) + ปัจจัยวันหยุด (Holidays) + ค่าความคลาดเคลื่อน (Error)
       - มีการกำหนด Hyperparameters อย่างละเอียดในฟังก์ชัน _build_model(history_size):
         1) growth = 'linear':
            กำหนดให้แนวโน้มหลัก g(t) เป็นแบบ Piecewise Linear ซึ่งมีความยืดหยุ่นสูง สามารถปรับเปลี่ยนความชันตามจุดเปลี่ยนแนวโน้ม (Changepoints) ในอดีตได้
         2) changepoint_prior_scale = 0.08:
            พารามิเตอร์ควบคุมความยืดหยุ่นในการตรวจจับจุดกลับตัวของแนวโน้ม ค่าตั้งต้นทั่วไปของ Prophet คือ 0.05 แต่เราปรับขึ้นเป็น 0.08 เพื่อให้โมเดลตอบสนองต่อรอบการกลับตัวของตลาดหุ้นได้ว่องไวขึ้น โดยไม่สูงจนเกิดปัญหา Overfitting ต่อสัญญาณรบกวนระยะสั้น
         3) weekly_seasonality = True:
            เปิดให้โมเดลเรียนรู้วงจรพฤติกรรมในรอบสัปดาห์ (วันจันทร์ถึงวันศุกร์ พฤติกรรมการซื้อขายมีความแตกต่างกันตามรอบสัปดาห์)
         4) yearly_seasonality = (history_size >= 252):
            เปิดใช้วงจรฤดูกาลรอบปีผ่านอนุกรมฟูเรียร์ (Fourier Series) โดยอัตโนมัติเมื่อมีข้อมูลราคาอย่างน้อย 1 ปี (252 วันทำการ) เพื่อจับรอบผลประกอบการประจำไตรมาส รอบจ่ายเงินปันผล และฤดูกาลของธุรกิจ
         5) daily_seasonality = False:
            ปิดการคำนวณวงจรระหว่างวัน เนื่องจากระบบใช้ข้อมูลความถี่รายวัน (End-of-Day) จึงไม่มีมิติเวลาเป็นชั่วโมงหรือนาที
         6) seasonality_mode = 'multiplicative':
            กำหนดให้ผลกระทบของฤดูกาลเป็นแบบ "คูณ" เข้ากับแนวโน้มหลัก: y = Trend x (1 + Seasonality)
            * เหตุผล: สอดคล้องกับพฤติกรรมหุ้นในความเป็นจริง เพราะเมื่อหุ้นราคาสูงขึ้น การแกว่งตัวของราคาจะมีสเกลที่ขยายตัวใหญ่ขึ้นตามสัดส่วนของระดับราคา
         7) interval_width = 0.90:
            กำหนดระดับกรอบความเชื่อมั่นที่ 90% สำหรับการคำนวณช่วงราคาต่ำสุดที่เป็นไปได้ (Lower Bound) และสูงสุดที่เป็นไปได้ (Upper Bound)
         8) uncertainty_samples = 500:
            ใช้การสุ่มตัวอย่างแบบ Bayesian Monte Carlo Sampling จำนวน 500 รอบ เพื่อประมาณการแจกแจงความน่าจะเป็นของกรอบความไม่แน่นอนได้อย่างเสถียรและแม่นยำ

   2.4 ระบบทดสอบและวัดความแม่นยำอัตโนมัติ (Hold-out Validation Engine):
       - ก่อนนำโมเดลไปใช้งาน ระบบมีกลไกตรวจสอบความแม่นยำในอดีต (Back-testing on Hold-out Window):
       - ซ่อนข้อมูลจริง 14 วันล่าสุด (Hold-out dataset = 14 วัน) ออกมาเก็บไว้
       - นำข้อมูลราคาก่อนหน้า 14 วันนั้นไปเทรนโมเดลจำลอง
       - ให้โมเดลจำลองลองพยากรณ์ราคา 14 วัน แล้วนำค่าพยากรณ์มาเทียบกับ "ราคาจริงที่เกิดขึ้นจริง"
       - คำนวณตัวชี้วัดสถิติระดับสากล 3 ตัว:
         * MAE (Mean Absolute Error): ค่าความคลาดเคลื่อนเฉลี่ยในหน่วยเงินจริง (บาท/ดอลลาร์)
         * MAPE (Mean Absolute Percentage Error): ค่าความคลาดเคลื่อนเฉลี่ยคิดเป็นเปอร์เซ็นต์
         * Accuracy %: ดัชนีความแม่นยำที่มนุษย์เข้าใจง่าย คำนวณจาก (100 - MAPE) เช่น ได้คะแนนความแม่นยำ 96.12%

   2.5 กระบวนการเทรน ทำนาย และจัดเก็บ (Fit, Predict & Persistence Workflow):
       1) รันคำสั่ง model.fit(frame) ด้วยข้อมูลราคาจริงทั้งหมด
       2) สั่ง future = model.make_future_dataframe(periods=7, freq=frequency) เพื่อสร้างตารางวันล่วงหน้า 7 วันทำการ
       3) สั่ง forecast = model.predict(future) ดึงเฉพาะแถวของ 7 วันข้างหน้า
       4) แปลงราคากลับจาก Log Scale เป็นราคาจริงด้วย np.expm1():
          - predicted_close = np.expm1(yhat)
          - predicted_lower = np.expm1(yhat_lower)
          - predicted_upper = np.expm1(yhat_upper)
          - trend_component = np.expm1(trend)
       5) บันทึกผลลัพธ์ลงฐานข้อมูล:
          - บันทึกราคาทำนาย 7 วันลงตาราง price_predictions
          - แปลงโครงสร้างโมเดลที่เทรนแล้วเป็นรูปแบบ JSON ด้วย model_to_json(model) แล้วบันทึกลงตาราง stock_models ในฟิลด์แบบ JSONB พร้อมค่าสถิติความแม่นยำ (Validation Metrics)
       6) กลยุทธ์การแคช (12-Hour Cache Policy):
          ระบบจะแคชผลการทำนายไว้ 12 ชั่วโมงในฐานข้อมูล หากมีผู้ใช้คนถัดไปเปิดดูหุ้นเดิม ระบบจะดึงผลจากฐานข้อมูลมาแสดงได้ทันทีในระดับมิลลิวินาที ไม่ต้องคำนวณใหม่ซ้ำซ้อน
       7) การเทรนแบบกลุ่มสำหรับ Admin (Batch Training):
          Admin สามารถกดปุ่มสั่งเทรนโมเดล AI หุ้นทุกตัวพร้อมกันในระบบ (run_batch_train_all) และระบบจะบันทึก Audit Log ลงตาราง system_logs เสมอ

   2.6 การนำผลพยากรณ์ไปใช้งานต่อ (Downstream Integration):
       - ด้านที่ 1 (Frontend Visualization - Plotly.js):
         พล็อตกราฟราคาจริงแบบ Candlestick แล้ววาดเส้นประสีทอง (Gold Dashed Line) เชื่อมต่อจากราคาปิดวันล่าสุดไปยังราคาทำนาย 7 วันข้างหน้า พร้อมระบายแถบเงาสีทองโปร่งแสง (Gold Confidence Ribbon) แสดงช่วงกรอบความเชื่อมั่น 90% (Lower - Upper Bound)
       - ด้านที่ 2 (Deep Analysis Dashboard):
         แสดงทิศทางแนวโน้ม (ขาขึ้น Uptrend / ขาลง Downtrend / ทรงตัว Sideway), แสดงตัวเลขคาดการณ์การเปลี่ยนแปลงใน 7 วัน เช่น "+3.45%", และแสดงตัวชี้วัดความน่าเชื่อถือของโมเดล (Accuracy %, MAE)
       - ด้านที่ 3 (AI Copilot RAG Ingestion):
         ส่งข้อมูลผลทำนาย 7 วัน ทิศทาง และคะแนนความแม่นยำ เข้าสู่หมวด [D5] ในคลังข้อเท็จจริง (Big Knowledge) เพื่อให้ AI Copilot ใช้ตอบคำถามผู้ใช้ได้อย่างแม่นยำ ไม่นั่งเทียนเดา


3. ลอจิกวิเคราะห์อารมณ์ข่าว (NLP Sentiment Analysis - TextBlob)
   [ไฟล์หลัก: backend/app/services/scraper_service.py และ sentiment_service.py]

   3.1 วัตถุประสงค์และบทบาทของ NLP ในระบบ TradeSensei:
       - รับผิดชอบการวิเคราะห์ข้อมูล "เชิงคุณภาพ (Qualitative Data)" จากข่าวสารและบทวิเคราะห์ในตลาด
       - แปลงข้อความข่าวสารภาษาธรรมชาติที่ไม่มีโครงสร้าง (Unstructured Text) ให้กลายเป็นตัวเลขชี้วัดทางสถิติ (Sentiment Polarity Score) เพื่อใช้ประเมินบรรยากาศการลงทุนและอารมณ์ของตลาด

   3.2 ขั้นตอนการดึงข่าวสาร (News Ingestion & Scraping Pipeline):
       - แหล่งข้อมูลหลัก: ดึงข่าวผ่าน yfinance.Ticker(symbol).news
       - การปรับมาตรฐานข้อมูล: ฟังก์ชัน _normalise_yahoo_news รองรับทั้งโครงสร้างข่าวแบบเดิมและแบบใหม่ที่มีการซ้อน Object ซับซ้อน
       - ระบบดึงข่าวสำรอง (Fallback RSS Engine): หาก yfinance ไม่มีข่าว หรือได้ข่าวน้อยกว่า 3 เรื่อง ระบบจะสลับไปดึง RSS Feed จาก 'https://feeds.finance.yahoo.com/rss/2.0/headline?s={symbol}' โดยอัตโนมัติ โดยใช้ requests ร่วมกับ BeautifulSoup(..., 'xml') แกะหัวข้อข่าว ลิงก์ และเวลาเผยแพร่
       - ระบบสำรองสำหรับหุ้นไทย: หากสัญลักษณ์หุ้นลงท้ายด้วย .BK แล้วยังไม่มีข่าว ระบบจะตัดนามสกุล .BK ออกแล้วค้นหาด้วยสัญลักษณ์หลัก
       - ระบบ Context Fallback เชิงโครงสร้าง: หากในตลาดยังไม่มีข่าวเปิดเผยเลย ระบบจะสร้างบทวิเคราะห์เชิงโครงสร้างตามหมวดหมู่อุตสาหกรรม (Category) และชื่อบริษัท เพื่อให้มีบริบทการลงทุนครบถ้วน
       - การป้องกันข่าวซ้ำ (Deduplication): ตรวจสอบ stock_id และ title ในฐานข้อมูลก่อนเสมอ หากมีอยู่แล้วจะไม่บันทึกซ้ำ
       - จัดเก็บลงตาราง news ในฐานข้อมูล PostgreSQL

   3.3 ขั้นตอนการประมวลผลภาษาธรรมชาติ (NLP Architecture with TextBlob):
       - นำหัวข้อข่าว (title) และเนื้อหาข่าว (content) มารวมกันเป็นข้อความเดียว
       - ส่งข้อความเข้าคลาส TextBlob(text) ซึ่งทำงานตามกระบวนการทางภาษาศาสตร์ (Linguistic Pipeline):
         1) Tokenization & Sentence Splitting:
            ตัดประโยคและแยกข้อความออกเป็นคำเดี่ยวๆ (Word Tokens)
         2) Lemmatization:
            แปลงคำกริยาและคำนามกลับสู่รูปรากศัพท์พื้นฐาน (Base Form) เช่น "dropped" -> "drop", "soaring" -> "soar"
         3) Part-of-Speech (POS) Tagging:
            วิเคราะห์หน้าที่ของคำในประโยค (เช่น Noun, Verb, Adjective, Adverb) โดยระบบจะเน้นคำคุณศัพท์ (Adjectives) และคำกริยาวิเศษณ์ (Adverbs) ที่สื่ออารมณ์ทางธุรกิจและการเงิน เช่น "strong", "growth", "bullish", "record", "crisis", "slump", "loss"
         4) Sentiment Lexicon Matching:
            นำคำศัพท์ไปเทียบกับคลังพจนานุกรมความรู้สึกที่ผ่านการกำหนดค่าน้ำหนักไว้ล่วงหน้า (Averaged Perceptron / Pattern Analyzer)
         5) Modifier & Negation Handling (การคิดคำขยายและคำปฏิเสธ):
            - คำขยายบอกระดับ (Intensifiers): เช่น "very high" หรือ "extremely strong" จะคูณเพิ่มน้ำหนักคะแนนความรู้สึก
            - คำปฏิเสธ (Negations): เช่น "not good" หรือ "never failed" ระบบจะสลับขั้วบวก/ลบของคำนั้นทันที ทำให้การแปลความหมายไม่ผิดเพี้ยน
       - คำนวณออกมาเป็น Polarity Score:
         ได้ตัวเลขทศนิยม 4 ตำแหน่ง ในช่วง [-1.0, +1.0]
         * -1.0 = เชิงลบสุดขีด (Extreme Negative)
         *  0.0 = เป็นกลาง ไร้อารมณ์ (Neutral)
         * +1.0 = เชิงบวกสุดขีด (Extreme Positive)

   3.4 การจัดกลุ่มประเภทและการบันทึกผล (Classification Threshold & Persistence):
       - นำ Polarity Score มาผ่านเกณฑ์ Threshold ที่ออกแบบเฉพาะสำหรับบริบทข่าวการเงิน:
         * ถ้าคะแนน > +0.1  -> จัดเป็น "Positive" (ข่าวเชิงบวก / ข่าวดี)
         * ถ้าคะแนน < -0.1  -> จัดเป็น "Negative" (ข่าวเชิงลบ / ข่าวร้าย)
         * อยู่ระหว่าง [-0.1, +0.1] -> จัดเป็น "Neutral" (ข่าวเป็นกลาง / รายงานตัวเลขทั่วไป)
       - สร้างข้อความอธิบายเหตุผลอัตโนมัติ (reason_text) เช่น "TextBlob polarity +0.45 — แง่บวก"
       - บันทึกผลลงตาราง news_sentiments (news_id, sentiment_score, sentiment_label, reason_text)
       - บันทึก Audit Log ลงตาราง system_logs (action_type = 'ANALYZE_NEWS_SENTIMENT') เพื่อให้ผู้ดูแลระบบตรวจสอบการทำงานย้อนหลังได้

   3.5 ดึงมาแล้วทำงานยังไงต่อ? การนำผลลัพธ์ไปใช้งานต่อ (Downstream Integration):
       - ด้านที่ 1 (การประมวลผลสรุปภาพรวม - get_sentiment_summary):
         ระบบจะดึงข่าวล่าสุด 10 เรื่องของหุ้นตัวนั้นมาคำนวณคะแนนเฉลี่ย (average_score), นับจำนวนข่าวเชิงบวก (positive_count), ข่าวเชิงลบ (negative_count), และข่าวที่เป็นกลาง (neutral_count), พร้อมกำหนดป้ายสถานะอารมณ์ตลาดโดยรวม (overall_label)
       - ด้านที่ 2 (แสดงผลบน Dashboard หน้าบ้าน):
         * ในแผง "ข่าวสารและบทวิเคราะห์": แสดงหัวข้อข่าว ลิงก์ และวันที่เผยแพร่
         * ในแผง "สรุปเชิงวิเคราะห์ (Deep Analysis)" ใต้กราฟ: แสดงสถานะอารมณ์ตลาดพร้อม Badge สี (เขียว=Positive, แดง=Negative, เทา=Neutral) และแถบคะแนนความรู้สึก
       - ด้านที่ 3 (ส่งเข้า Big Knowledge ของ Sensei Copilot - RAG):
         ข้อมูลคะแนนเฉลี่ย สัดส่วนข่าวบวก/ลบ/กลาง และตัวอย่างหัวข้อข่าวล่าสุด 4 เรื่อง จะถูกแพ็กเข้าหมวด [D4] ในคลังข้อเท็จจริง เมื่อผู้ใช้ถาม AI Copilot เกี่ยวกับข่าวสารหรือบรรยากาศการลงทุน AI จะอ้างอิงข้อมูลชุดนี้ไปตอบอย่างเป็นรูปธรรม มีหลักฐานรองรับ ไม่มโนข้อมูลขึ้นมาเอง


4. ลอจิกจำลองผลตอบแทน Time Machine (Backtest) เปรียบเทียบเงินฝาก
   [ไฟล์หลัก: backend/app/services/backtest_service.py]
   - สูตรที่ใช้: เงินรวม = เงินต้น x (1 + อัตราดอกเบี้ย)^(จำนวนวัน / 365)
   - ทำไมต้องใช้สูตรนี้:
     1) เป็น "สูตรดอกเบี้ยทบต้นตามสัดส่วนวันจริง" ตามมาตรฐานการเงินสากล
     2) รองรับทั้งกรณีดูย้อนหลังสั้นๆ (1-6 เดือน) และกรณียาวเกิน 1 ปี (18-24 เดือน) ได้อย่างแม่นยำด้วยสมการเดียว ดอกเบี้ยปีแรกจะถูกนำไปทบต้นในปีที่สองอย่างถูกต้อง
     3) เปรียบเทียบกับหุ้นอย่างยุติธรรม (Apple-to-Apple) เพราะราคาหุ้นเติบโตแบบทบต้น ดอกเบี้ยเงินฝากจึงต้องคิดแบบทบต้นเช่นกัน
   - ประโยชน์ที่แท้จริงของสูตรนี้:
     1) ใช้เป็นเกณฑ์เปรียบเทียบที่ไร้ความเสี่ยง (Risk-Free Benchmark): เงินฝาก 2.5%/ปี คือสิ่งที่ได้แน่นอน 100% โดยไม่ต้องเสี่ยงขาดทุน
     2) เตือนสตินักลงทุนเรื่อง "ต้นทุนค่าเสียโอกาส" (Opportunity Cost): เช่น เอาเงิน 100,000 บาท ไปเสี่ยงในหุ้น 1 ปี ได้กำไร 1,000 บาท (+1%) ดูเหมือนได้กำไร แต่ถ้าฝากธนาคารเฉยๆ จะได้ 2,500 บาท (+2.5%) โดยไม่ต้องนอนไม่หลับ สูตรนี้จึงช่วยเตือนสติว่าคุ้มค่าที่จะเสี่ยงหรือไม่
   - ตัวอย่างให้เห็นภาพชัดเจน:
     * สมมติใส่เงินต้น 100,000 บาท เลือกดูย้อนหลัง 6 เดือน (ครึ่งปี)
     * ถ้าครบปีได้ 2,500 บาท แต่ฝากครึ่งปีจะได้ดอกเบี้ยประมาณ 1,250 บาท
     * เงินรวมจากการฝากธนาคารจะได้ 101,250 บาท (กำไร +1.25%)
   - ระบบจะนำไปเทียบกับราคาหุ้นจริงในช่วง 6 เดือนเดียวกัน:
     * ถ้าหุ้นขึ้น +10% (เงินโตเป็น 110,000 บาท) -> ระบบสรุปว่า "หุ้นชนะเงินฝาก (+10% vs +1.25%)"
     * ถ้าหุ้นร่วง -5% (เงินเหลือ 95,000 บาท) -> ระบบสรุปว่า "หุ้นแพ้เงินฝาก (-5% vs +1.25%)"


5. ลอจิกระบบผู้ช่วยอัจฉริยะ (Sensei Copilot - Gemini RAG & Fallback)
   [ไฟล์หลัก: backend/app/services/copilot_service.py และ copilot_rules.py]
   - สถาปัตยกรรม RAG (Retrieval-Augmented Generation):
     ระบบไม่ได้ให้ AI นึกคำตอบเอาเอง แต่ดึงข้อเท็จจริง 5 ส่วนจากฐานข้อมูลเรา (เรียกว่า Big Knowledge) มัดรวมเป็นบริบทส่งให้ AI:
     [D2] ข้อมูลหุ้นและหมวดหมู่
     [D3] ราคาจริง OHLCV และค่าเฉลี่ยทางเทคนิค SMA20, SMA50
     [D4] ข่าวล่าสุด และคะแนนอารมณ์ข่าว TextBlob
     [D5] ผลการทำนายราคา Prophet 7 วัน, ทิศทาง, และ Accuracy %
     [D7] ผลการจำลอง Time Machine ย้อนหลัง
   - การควบคุมพฤติกรรม (Persona & Guardrails):
     * กำหนดบุคลิก Trade Sensei แทนตัวเองว่า "ผม" สุภาพ ให้คำแนะนำกระชับ
     * มีตัวคัดกรองคำถาม: หากถามนอกเรื่องที่ไม่เกี่ยวกับหุ้น (สูตรอาหาร, กีฬา, คำถามทั่วไป) ระบบจะตรวจจับและปฏิเสธอย่างสุภาพทันที
   - ระบบความต่อเนื่องในการให้บริการ (High Availability Fallback):
     * ในกรณีที่ Google Gemini API ติดข้อจำกัด Rate Limit (โควต้าฟรี 20 ครั้ง/วัน) หรือเน็ตขัดข้อง
     * ระบบมี Deterministic Rule-Based Generator ดักไว้ เพื่อนำข้อมูล Big Knowledge มาตอบเป็นภาษาไทยแบบโครงสร้างข้อๆ ทันที ทำให้หน้าเว็บไม่มีวันแครชหรือขึ้น Error


6. ลอจิกการแบ่งสิทธิ์และระบบความปลอดภัย (Security & Roles)
   - ผู้ใช้ทั่วไป (Guest): ดูกราฟราคาจริงย้อนหลังและข่าวได้ แต่ปุ่มทำนาย, Backtest, และ Copilot จะถูกล็อกไว้
   - สมาชิก (Member): ยืนยันตัวตนผ่าน JWT Authentication, รหัสผ่านแฮช Bcrypt, มีระบบ OTP 6 หลักทางอีเมล (Resend) กู้คืนรหัสผ่านที่หมดอายุใน 10 นาที, ปลดล็อกทุกฟีเจอร์พรีเมียม
   - ปุ่มรีเฟรชข้อมูล (Refresh - ขอบเขต 1.3.2.4): สมาชิกสามารถกดปุ่ม "↻ รีเฟรช" ที่หัวกราฟ เพื่อล้างแคชและดึงราคา OHLCV ข่าว และผลวิเคราะห์ล่าสุดจากฐานข้อมูล PostgreSQL มาแสดงผลได้ทันที
   - ผู้ดูแลระบบ (Admin): มีหน้าจอควบคุมแยกต่างหาก สั่งดึงข้อมูลตลาด (Scraper), สั่งเทรนโมเดล AI หุ้นทุกตัวพร้อมกัน (Batch Processing), จัดการผู้ใช้, และมีหน้าต่างบันทึกกิจกรรมระบบ (System Logs)


7. สรุปการผสานพลังร่วมกัน (Synergy between ML + NLP + Copilot)
   - ML (Facebook Prophet) -> วิเคราะห์ข้อมูล "เชิงปริมาณ" (กราฟ, สถิติ, ทิศทางราคา 7 วัน)
   - NLP (TextBlob)       -> วิเคราะห์ข้อมูล "เชิงคุณภาพ" (ข่าวสาร, อารมณ์ตลาด, บรรยากาศการลงทุน)
   - AI Copilot (Gemini)  -> นำผลของทั้ง ML + NLP มาร้อยเรียงและอธิบายให้นักลงทุนฟังเป็นภาษาไทยที่เข้าใจง่าย
